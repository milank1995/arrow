## 1. Code changes

### 1a. Committed — `4b09540 fix(analytics): deduplicate events and rename custom ad impression to ad_shown`
File: `app/src/main/java/com/arrowaway/puzzle/analytics/AnalyticsManager.kt`
- `logScreenView`: removed the duplicate `logEvent("screen_view")`. `FirebaseAnalytics.Event.SCREEN_VIEW` is the same string, so every screen was counted twice.
- `logLevelStart`: removed the duplicate `logEvent("level_start")`, for the same reason.
- `logAdImpression`: the custom event is renamed from `ad_impression` to `ad_shown`. `ad_impression` is reserved for the AdMob SDK's automatic event, which carries revenue, so the old name double-counted impressions.
- Effect after release: GA4 `screen_view` and `level_start` counts drop by about half. That is correct, not a regression.

### 1b. NOT committed yet — Google UMP consent form + privacy text
Release build (`assembleRelease`) and unit tests (`testDebugUnitTest`) pass. **Not yet tested on a real device.**

| File | Change |
|---|---|
| `app/build.gradle.kts` | Added `com.google.android.ump:user-messaging-platform:3.1.0` |
| `ads/ConsentManager.kt` (new) | Wraps the UMP SDK: `gatherConsent(activity, onComplete)`, `canRequestAds(context)`, `isPrivacyOptionsRequired(context)`, `showPrivacyOptionsForm(activity)`, `resetForTesting(context)` (debug only). Has debug flags `DEBUG_FORCE_EEA` (default `false`) and `DEBUG_TEST_DEVICE_HASHED_IDS`. |
| `ArrowAwayApplication.kt` | Calls `AdManager.initialize` only if `ConsentManager.canRequestAds()` is already true (returning users, or users outside consent regions). |
| `MainActivity.kt` (`onCreate`) | Calls `ConsentManager.gatherConsent(this)`, then `AdManager.initialize(applicationContext)` if consent allows ads. |
| `ads/AdManager.kt` | `initialize()` is guarded by an `AtomicBoolean` so it runs only once. New `isInitialized` property. `preloadRewardedAd` and `preloadInterstitialAd` return early until initialised. |
| `ui/components/BannerAdView.kt` | Returns early (no banner) if `!AdManager.isInitialized`. |
| `ui/screens/SettingsScreen.kt` | New "Privacy Options" row under "Privacy Policy", shown only when `ConsentManager.isPrivacyOptionsRequired()` is true, which opens the UMP privacy options form. The in-app Privacy Policy dialog text is rewritten to match the new website policy. The old text wrongly said users could "disable tracking in Settings"; that toggle is dev-mode only. |

**How to test the consent form:** set `DEBUG_FORCE_EEA = true` in `ConsentManager.kt` and run a debug build. Logcat prints the device's hashed test ID; add it to `DEBUG_TEST_DEVICE_HASHED_IDS` and run again, and the European consent form should appear. Set the flag back to `false` afterwards. It has no effect in release builds anyway.
